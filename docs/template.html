Disk Analyzer 설명서

Windows 10/11 용 디스크 용량 분석 프로그램. WizTree / TreeSize 와 같은 목적이며 빠른 스캔 · 한눈에 읽히는 화면 · 대용량에서의 안정성을 우선합니다.

.NET 9 · WPF · x64 단일 exe (.NET 설치 불필요) 2,913만 파일 실측 삭제 전 보호 등급 재검증

이 문서의 그림은 draw.io 로 만든 다이어그램이며, 확대 · 이동 · 레이어 보기가 됩니다. 그림 아래의 원본 .drawio 받기 로 원본을 받아 draw.io 에서 편집할 수 있습니다.

⚠ draw.io 뷰어를 불러오지 못했습니다(인터넷 연결 필요). 그림 대신 docs/diagrams/*.drawio 파일을 draw.io 에서 직접 열어 보세요.

빠른 시작

  1. dist\DiskAnalyzer.exe 를 실행합니다. 복사해서 그대로 쓸 수 있고 .NET 을 따로 설치하지 않아도 됩니다.
  2. 왼쪽 저장소 사이드바에서 드라이브 카드를 누르고 [선택 드라이브 스캔] 을 누릅니다(카드를 더블클릭해도 스캔). 사이드바는 헤더 맨 왼쪽 아이콘으로 접고 펼 수 있고, 접은 상태는 다음에 열 때도 유지됩니다.
  3. 스캔이 끝나면 폴더 · Treemap · 선버스트 · 큰 파일 · 파일 유형 · 정리 추천 탭에서 결과를 봅니다.
  4. 탐색기에서 폴더를 창에 떨어뜨려도 그 대상을 스캔합니다. 자주 보는 폴더는 Ctrl+D 로 고정해 두면 드라이브 카드 아래에 ★ 카드로 남아 바로 다시 스캔할 수 있습니다.

명령줄 옵션 (자동화·검증용)

dist\DiskAnalyzer.exe "C:\Users" --tab 5     # 경로를 주면 바로 스캔, --tab 으로 시작 탭 지정
# 탭 번호: 0 = 폴더 · 1 = Treemap · 2 = 선버스트 · 3 = 큰 파일 · 4 = 파일 유형 · 5 = 정리 추천 · 6 = 빠른 이동

관리자 권한이 아니면 헤더에 [관리자 권한으로 다시 실행] 버튼이 뜹니다. 일반 권한에서도 Compatibility Scan 으로 완전히 동작하고, 관리자로 실행하면 드라이브 루트 스캔에서 NTFS Fast Scan 을 시도합니다. Fast Scan 은 아직 관리자 권한에서 실측 검증을 하지 못했습니다(실패하면 자동으로 Compatibility 로 내려갑니다).

화면 사용법

스캔

  • 선택 드라이브 스캔 / 전체 스캔 / 새로고침 / 스캔 중지 는 위쪽 버튼입니다. 스캔 중에도 화면이 멈추지 않고 진행률이 실시간으로 갱신됩니다.
  • 이전 스캔 결과는 캐시되어 프로그램을 다시 열면 바로 보입니다(설정 → Cache Results). 최신 상태는 새로고침으로 확인하세요.
  • 접근 거부 폴더는 건너뛰고 스캔은 계속됩니다.

스캔 제외 규칙

설정 → 스캔 제외 칸에 한 줄에 하나씩 적고 [제외 규칙 적용] 을 누릅니다. 다음 스캔부터 적용되고 설정은 저장되어 다음에 프로그램을 열 때도 유지됩니다.

대소문자는 구분하지 않습니다. 제외한 것이 있으면 스캔이 끝날 때 제외 규칙 적용: 폴더 N · 파일 M 으로 알려 주므로 용량이 왜 덜 나오는지 헷갈리지 않습니다. 폴더 변경 감지와 F5 새로고침도 같은 규칙을 씁니다.

경로 규칙은 폴더에만 적용됩니다. 파일마다 전체 경로 문자열을 만들면 그것만으로 스캔이 수십 초 느려지기 때문입니다 (같은 이유로 보호 등급 판정도 2단 구조를 씁니다). 특정 파일을 빼려면 확장자나 이름 규칙을 쓰세요.

캐시에는 제외를 적용한 결과가 저장됩니다. 규칙을 바꾸면 다시 스캔해야 반영됩니다.

폴더 ↔ Treemap 연동

두 탭은 같은 위치 상태 하나를 공유합니다. 그래서 어느 쪽에서 이동해도 다른 쪽이 같은 폴더를 보여 줍니다.

  • 이동 막대(◀ ▶ ▲ 루트 · 경로 막대)는 탭 위에 있으며 폴더·Treemap 이 함께 씁니다.
  • Treemap 에서 폴더를 더블클릭하면 탭을 바꾸지 않고 그 폴더로 들어갑니다. 돌아올 때는 ▲ / 루트 / 뒤로를 씁니다.
  • [분할 보기] 를 켜면 폴더 목록(왼쪽)과 Treemap(오른쪽)이 나란히 보입니다. 가운데 경계를 끌어 너비를 조절하고, 다시 누르면 원래대로 돌아갑니다.
  • 목록에서 고른 항목은 Treemap 에서 테두리로 강조되고, Treemap 사각형을 누르면 목록에서 선택되어 그 위치로 스크롤됩니다. 깊은 곳의 사각형을 눌렀다면 현재 폴더 바로 아래에서 그것을 품은 항목이 선택됩니다.

선버스트

같은 폴더를 비율로 보는 화면입니다. 안쪽 겹이 바깥 겹을 품고 있어 계층이 그림 자체로 읽히고, 조각에는 이름을 쓰지 않습니다 — 이름은 오른쪽 목록이 맡습니다.

동작결과
조각에 마우스를 올림이동하지 않고 그 폴더의 내용이 오른쪽 목록에 뜹니다. 훑어보는 데 클릭이 들지 않습니다(제목 아래 가리키는 중 표시).
조각을 누름그 폴더로 들어갑니다. 폴더 탭 · Treemap 과 같은 위치 상태라 경로 막대와 ◀ ▶ ▲ 가 그대로 듣습니다.
가운데 원을 누름상위 폴더로. 원 안의 숫자는 현재 폴더 전체 크기입니다.
조각을 끌어 아래로수집함에 담깁니다(아래 참고).

색은 위치에서 나옵니다. 조각의 색조는 각도만으로 정해지므로(원 한 바퀴에 색조 0°→270°) 자식은 부모와 같은 색 계열이 되고, 이웃한 조각이 같은 색이 되는 일이 없으며, 오른쪽 목록의 색 점이 링과 저절로 맞습니다. 파일은 회색입니다.

  • 따로 그리기엔 너무 얇은 항목은 버리지 않고 작은 항목 N개 한 조각으로 합칩니다 — 원 한 바퀴는 언제나 현재 폴더 전체입니다. 개별로 보려면 폴더 탭에서 확인하세요.
  • 드라이브 루트를 스캔했다면 목록 맨 아래에 숨은 공간(드라이브 사용량 − 스캔 합계)과 여유 공간이 붙습니다. 접근 권한이 없어 못 읽은 용량이 얼마인지 숨기지 않기 위한 것이고, 여유 공간은 링에 그리지 않습니다.
  • 스캔 중에는 현재 폴더의 한 겹만 그립니다(끝나면 하위 겹까지 함께 보입니다).

링을 무엇으로 칠할지

오른쪽 목록 위의 색 선택(또는 Ctrl+T)으로 바꿉니다. 각도는 그대로고 색만 바뀝니다 — 같은 그림에 다른 질문을 거는 것입니다.

기준색이 뜻하는 것답하는 질문
크기(기본)위치(각도)에서 나온 색무엇이 큰가
정리 추천정리 점수 — 초록(참고) → 빨강(우선 정리). 후보가 아니면 회색 무엇을 지워도 되는가
이전 대비 증감직전 스캔 대비 — 붉을수록 늘고, 푸를수록 줄고, 보라는 그때 없던 항목 무엇이 늘었는가

색만으로는 "얼마나"를 알 수 없으므로, 조각을 가리키면 아래 설명 줄에 이전 120 MB → +80 MB · 정리 추천 72점 처럼 숫자로도 적힙니다.

증감을 보려면 같은 대상을 두 번 스캔해야 합니다. 새 스캔을 저장할 때 직전 결과를 따로 밀어 두고 그것과 비교합니다. 비교할 것이 없으면 그 기준은 켜지지 않고 이유를 알려 줍니다.

수집함

화면 아래에 항상 붙어 있는 삭제 대기 바구니입니다. 탭이나 폴더를 옮겨도 담긴 것이 유지되므로 "여기서 하나, 저기서 하나" 를 모아 한 번에 지울 수 있습니다.

  • 담기 — 링에서 아래로 끌기 / 가운데 버튼 / 우클릭 [수집함에 담기] / Ctrl+Delete. 폴더 목록·큰 파일 탭에서는 고른 줄들이 한 번에 담깁니다.
  • P0 는 담기지 않습니다. 삭제 확인 창에서 거르는 것이 아니라 담는 순간 막고 이유를 알립니다.
  • 폴더를 담으면 그 안에 담겨 있던 것은 빠집니다. 합계가 두 번 세어지지 않습니다.
  • [목록] 으로 펼쳐 개별 ✕ 로 빼고, [비우기] 로 전부 비웁니다.
  • [삭제...] 는 기존 삭제 대상 확인 창을 그대로 거칩니다. 수집함은 고르는 곳이지 지우는 곳이 아닙니다. 보호 등급은 담을 때와 지울 때 각각 다시 판정합니다.
  • [대기열로](Ctrl+Shift+M) — 지우는 대신 옮깁니다. 담은 것을 빠른 이동 대기열로 넘겨 다른 드라이브로 옮길 수 있습니다. 보낸 뒤 수집함은 비워집니다.

검색

  • 검색창에 입력하고 Enter 또는 [검색]. 결과는 폴더 목록에 나옵니다(다른 탭에서 눌러도 폴더 탭으로 옮겨집니다).
  • 글자만 입력하면 부분 일치(대소문자 무시), * ? 를 쓰면 이름 전체가 패턴과 맞아야 합니다. log → catalog.txt 도 일치 / *.log → app.log 만 일치 / log_??.txt → log_01.txt.
  • 범위는 전체 또는 현재 폴더 하위 중에서 고릅니다.
  • 결과가 5,000건을 넘으면 크기 상위 5,000건과 전체 건수를 상태바에 알려 줍니다. 크기·확장자 필터를 바꾸면 검색이 다시 실행됩니다.
  • 스캔이 끝난 뒤에 검색할 수 있습니다(스캔 중에는 안내 메시지가 뜹니다).

정리 추천과 폴딩

정리 추천은 두 개의 독립된 질문에 답합니다. "삭제해도 되는가"(보호 등급 P0~P3)와 "삭제할 가치가 있는가"(점수 0~100). 모든 후보에는 선정 이유 문장이 붙고, 프로그램은 삭제 안전성을 단정하지 않습니다.

  • 기준: 오래된 기준(30일~2년) · 최소 크기 · 카테고리 · 정렬. 바꾸면 바로 다시 분석합니다.
  • 보기 방식: 폴더 트리(기본) · 파일별 · 경로별 · 유형별 · 정리 이유별. 보기를 바꿔도 파일 시스템을 다시 분석하지 않습니다.
  • [추천 항목 선택] 은 정리 가능성 높음 만 선택합니다. 확인 필요 / 비추천 항목은 건드리지 않습니다.

폴더 트리와 반복 패턴 접기

같은 이름의 파일이 수백 개 나열되어 한눈에 안 보이는 문제를 줄이려고, 후보를 폴더별로 묶고 이름 패턴이 반복되면 한 줄로 접습니다.

(b) 서로 다른 폴더에 있는 같은 이름 (같은 드라이브)obj\Debug\a.pdb, obj\Release\a.pdb공통 상위 폴더 아래 a.pdb ×N건
  • 5건 이상일 때만 접습니다. ▸ 를 펼치면 원래 후보가 그대로 나옵니다 — 접는 것은 보여 주는 방식뿐이며 후보를 없애지 않습니다.
  • 폴더·묶음의 체크박스는 하위 전체 선택/해제이고, 일부만 선택되면 ▣ 로 표시됩니다. P0 는 어떤 체크박스로도 선택되지 않습니다.
  • 후보가 하나뿐인 폴더 체인은 C:\Users\me\AppData 처럼 한 줄로 합칩니다. [모두 펼치기 / 모두 접기] 로 한꺼번에 조절합니다.
  • 항목을 삭제한 뒤에도 펼쳐 둔 위치가 유지되고, 상단 합계가 즉시 갱신됩니다.

삭제

삭제 버튼을 눌러도 즉시 지우지 않습니다. 반드시 삭제 대상 확인 창을 거칩니다.

  1. 폴더 · 큰 파일 · 정리 추천에서 항목을 고르고 [삭제...].
  2. 확인 창에서 파일명·경로·크기·수정일·보호 등급·경고를 보고 개별로 제외합니다. 체크가 바뀔 때마다 예상 확보 용량이 다시 계산됩니다.
  3. [휴지통으로 이동](기본) 또는 [영구 삭제...](빨간 테두리 + 2단계 확인).
  4. 진행률과 현재 경로가 표시되고, 끝나면 성공 / 실패 / 이미 존재하지 않음이 집계됩니다. 성공한 항목은 재스캔 없이 화면에 바로 반영됩니다.
등급의미확인 창에서
P0절대 보호 (pagefile.sys · System32 · 레지스트리 하이브 · 드라이버 · 부팅 영역)체크박스 비활성, 전체 선택에서도 제외
P1고위험 (Program Files · ProgramData · AppData · Junction · 사용 중인 파일)기본 체크 해제, 강한 경고
P2정리 가능 (Temp · Cache · 오래된 로그 · 빌드 산출물)기본 선택
P3일반 파일 (다운로드 · 동영상 · 압축 · 문서)기본 선택

삭제 직전에 다시 판정합니다. 스캔 시점의 판정을 그대로 믿지 않고, 이미 사라졌으면 건너뛰고, 그 사이 P0 가 되었으면 시도조차 하지 않으며, 다른 프로그램이 쓰고 있으면 P1 로 올립니다. 한 파일이 실패해도 전체 작업은 계속됩니다.

우클릭 메뉴의 휴지통으로 이동 / 영구 삭제 는 확인창을 거치지만(시스템 영역은 한 번 더) 위의 P0~P3 재판정 창을 거치지 않는 단순 경로입니다. 여러 항목이나 폴더는 [삭제...] 버튼(확인 창) 사용을 권합니다.

동작 원리

전체 구조

UI 코드에는 파일 시스템 접근이 한 줄도 없고, 엔진(DiskAnalyzer.Core)은 UI 타입을 전혀 참조하지 않습니다. UI 는 150ms 주기의 타이머로 엔진이 게시한 최신 스냅샷을 당겨 읽습니다(pull). 엔진이 UI 로 이벤트를 밀어 넣으면 파일이 많을수록 Dispatcher 큐가 넘치기 때문입니다.

{{diagram:01-architecture|그림 4. 프로젝트 · 계층 구조}}

스캔 파이프라인

  • 스레드: UI 1 · Worker(HDD 2 / SSD min(코어, 12)) · Aggregator 1 · 정리 분석 1(일시). Aggregator 가 NodeStore 의 유일한 writer 라서 lock 이 하나도 없습니다.
  • 재귀 함수로 디스크를 돌지 않고 디렉터리 큐를 워커가 한 단계씩 열거합니다 → 취소가 즉시 먹고 병렬화가 가능합니다.
  • 결과는 제한된 채널로 전달되어, Aggregator 가 밀리면 워커가 자연스럽게 기다립니다(backpressure).
  • NTFS Fast Scan: $MFT 를 4MB 단위로 순차 읽어 직접 파싱합니다. 불가능하면(비 NTFS · 권한 없음 · 하위 폴더 스캔 · 파싱 실패) 예외 없이 Compatibility 로 전환하고 이유를 알립니다.
{{diagram:02-scan-pipeline|그림 5. 스캔 파이프라인과 NTFS Fast Scan}}

데이터 모델

NodeStore 는 인덱스 기반 트리를 Structure of Arrays 로 보관합니다.

기법효과
SoA + 인덱스 트리파일당 객체 0개 (객체 헤더 16B × N 제거)
StringPool (2MB char[] 청크)이름 문자열 객체 N개 → 청크 N/50만 개
전체 경로 미저장공통 prefix 중복 제거 — 경로는 parentId 체인으로 필요할 때만 만듦
일 단위 생성일·접근일파일당 16B 절약
tombstone 삭제인덱스가 곧 노드 id 라서 배열을 압축하지 않음
Lazy 인덱스폴더별 파일 목록(CSR)은 스캔 후 처음 필요할 때만 생성

핵심 불변식: 자식 폴더 id > 부모 폴더 id. Compatibility 스캔은 BFS 라 자연히 성립하고, Fast 스캔은 루트에서 BFS 로 다시 번호를 매겨 복구합니다. 덕분에 폴더 크기 롤업이 역순 1패스 O(D) 로 끝나고 재귀도 두 번째 순회도 필요 없습니다.

for (int i = n - 1; i > 0; i--) {          // 폴더 크기 롤업 = 역순 1패스
    int p = parent[i];
    totalSize[p] += totalSize[i];
    totalFiles[p] += totalFiles[i];
    totalDirs[p]  += totalDirs[i] + 1;
}

보호 등급 판정

보호 여부를 먼저 결정하고, 그 다음에 정리 가치를 봅니다. P0/P1 이면 점수 계산 자체를 건너뜁니다. 파일명만으로 판단하지 않습니다(D:\Backup\pagefile.sys 는 P0 가 아님). 확장자만으로 P1 을 만들지도 않습니다(Downloads\old_setup.exe = P3).

{{diagram:04-protection-levels|그림 6. 보호 등급 판정 순서와 정리 추천 점수}}

파일이 2,913만 개인 드라이브에서 파일마다 경로를 만들면 그것만으로 수십 초가 걸립니다. 그래서 2단으로 판정합니다: ① 폴더가 물려받은 분류 플래그로 경로 문자열 없이 대량 제외 → ② 크기·나이 조건을 통과한 수천 건만 실제 경로로 정밀 판정. (287,390 파일 트리 전체 분석 26ms)

삭제 엔진 (FastDeleter)

영구 삭제는 휴지통이 필요 없으므로 Windows 셸(SHFileOperation)을 거치지 않고 Win32 API 를 직접 호출합니다. 셸은 항목마다 초기화·사전 열거·변경 알림을 하고 한 스레드에서 순서대로 처리해서 파일이 많은 폴더에서 매우 느렸습니다.

  • 같은 깊이의 폴더를 병렬로 열거하며 열거 결과의 파일을 바로 지우고, 비어 버린 폴더는 깊은 곳부터 제거합니다.
  • Junction / 심볼릭 링크는 따라가지 않고 링크만 지웁니다. \\?\ 접두사로 260자를 넘는 경로도 지웁니다.
  • 실패하면 단계적으로 다시 시도합니다: 일반 삭제 → 읽기 전용 등 속성 해제 → POSIX 삭제 시맨틱.
  • 휴지통 이동은 되돌릴 수 있어야 하므로 여전히 셸을 쓰며 순차 처리합니다. 다른 프로세스가 FILE_SHARE_DELETE 없이 열어 둔 파일과 실행 중인 exe 는 OS 규칙상 지울 수 없어 [사용 중] 으로 보고합니다.

DiskAnalyzer.Bench.exe C:\                     # 전체 드라이브 스캔 속도

알려진 제약

  • NTFS Fast Scan 미검증 — 관리자 권한에서 DiskAnalyzer.Bench.exe C:\ --mode fast 로 먼저 확인하세요. 실패하면 자동으로 Compatibility 로 내려갑니다.
  • "현재 로드된 커널 드라이버"는 실제 로드 목록을 조회하지 않고 System32\drivers 전체를 보수적으로 P0 처리합니다. "실행 중인 프로그램"도 파일 잠금 여부로 판정합니다.
  • 중복 가능 파일은 이름 + 크기만 비교합니다(내용을 읽지 않으므로 확정이 아님).
  • 폴더의 "마지막 접근일"은 표시하지 않습니다. 접근일 기록이 꺼져 있으면 수정일 기준으로만 판단하고 화면에 알립니다.
  • 삭제 직후 목록은 내부 모델 기준으로만 정확합니다. 외부 변경까지 맞추려면 새로고침이 필요합니다.
  • P2 조건은 "재생성 가능한 위치 + 30일 이상 미수정"이라 오늘 빌드한 Debug 폴더는 자동 선택 대상이 아닙니다(CleanupAnalyzer.ResolveP2() 의 ageDays >= 30 조정).
